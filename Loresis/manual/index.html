使用手册

从第一次游玩到控制写作效果，再到制作角色卡和创世 Skill。初次使用从快速入门开始，也可以通过目录查阅具体功能。

一、简介：认识 Loresis

认识 Loresis

Loresis 是围绕角色卡展开的故事游玩与创作工作台。你可以导入现成角色卡，扮演故事中的主角，让模型回应你的对白和行动；也可以在创世中制作自己的角色卡，再开始游玩。

你可以做什么

目标使用的功能
直接开始一个故事导入角色卡，选择开场白和主角，创建会话
让故事持续发展在故事输入框提交行动、对白或叙事要求
查看过程中的变化查看历史总结、故事状态与角色卡提供的状态栏
调整写作效果选择写手，编辑世界书，查看实际提示词
制作自己的内容在创世中编辑原生角色卡、世界书、开场和互动选项
复用创作方法与素材使用资源仓和创世 Skill

模型决定生成能力，角色卡提供故事基础，写手指导表达方式。它们可以分别配置，不需要先学会全部功能才能开始。

主要入口

  • 角色卡：查找、导入、查看角色卡，从角色卡创建或继续会话。
  • 故事：实际游玩，阅读章节、输入行动、查看状态和历史总结。
  • 创世：制作和修改角色卡草稿，使用创世助手协作。
  • 写手：管理写作指导，导入酒馆预设或编辑自己的写手。
  • 资源仓：整理可供创作参考和复用的材料。
  • 设置：配置模型、主角模板、快速提示词、外观与小精灵。

待补截图：工作台全貌，标出角色卡、故事、创世、写手、资源仓和设置入口。

从酒馆迁入

角色描述、人格、场景、示例对话、开场白和世界书等概念仍然适用。创世直接围绕原生角色卡字段编辑，另有 Loresis 的互动选项。

酒馆预设从写手入口导入；酒馆扩展涉及的脚本、Regex、宏和状态栏，需要在实际卡片中检查效果。成功导入不代表所有外部扩展都能完整运行。

推荐阅读路线

初次使用先读配置模型、导入角色卡和开始第一次游玩。遇到陌生概念时查基础概念。

已经能正常游玩后，从总目录查找输入指令、右侧栏、写手和创世等专题。

基础概念

角色卡与会话

角色卡提供故事起点，可以包含一个人物，也可以描述一个场景、一群人物或整个世界。

会话是基于这张卡的一次具体游玩，包含本局的开场、后续章节和状态。同一张卡可以创建多个会话，分别尝试不同开场或行动。继续已有会话和创建新会话是两件事：前者接着已有经历，后者开始另一局。

主角与卡中的角色

主角是你在本局扮演的身份。主角模板提供名字、别称、性格和背景等信息，创建会话时选择。

角色卡中的人物是故事参与者，不一定就是玩家主角。例如，一张旅馆故事卡可以提供老板、旅客和旅馆背景，你则选择一位调查员作为主角。

模型与写手

模型连接决定由哪个模型处理请求；写手决定如何组织写作要求。

在设置中更换写手助手使用的模型，与在故事中更换写手不是同一个操作。前者换生成服务或模型，后者换文风、叙事方法和输出偏好。

世界书与全局世界书

世界书以词条保存人物、地点、规则和其他资料。词条可以常驻参与注入，也可以按关键词匹配。

将一张卡设置成全局世界书后，其中的世界书词条可以参与其他角色卡的匹配。全局世界书并不表示其中每条内容每轮都会进入提示词；还要结合词条启用、匹配和实际注入情况判断。

原文、展示与润色

章节原文是模型生成并保存的内容。阅读界面可能对它进行排版、处理展示标记，或显示卡片提供的 HTML 内容。

润色是针对已有章节另行生成的阅读稿。它不替换原文章节，也不作为后续剧情、状态和历史总结的输入。

状态栏、MVU 与历史总结

  • 状态栏侧重展示。具体显示什么，由角色卡的设计决定。
  • MVU用于角色卡定义的变量更新，例如金钱、时间、关系值等；只有设计了相应能力的卡片才有对应变量。
  • 故事状态是本局的状态信息，与卡片自定义 MVU 变量需要分别理解。
  • 历史总结记录各章经历的摘要，帮助查看和组织历史内容。

不要仅凭状态栏的外观判断变量是否已经正确更新，也不要把章节总结当作全部原文。

创世草稿与角色卡

创世草稿是正在编辑的创作内容。保存成角色卡后，才得到可从角色卡入口使用的成果。

创世 Skill 是创作方法参考，例如如何设计人物关系或写开场。它不是角色卡本身，也不是安装到应用中的可执行插件。

二、快速入门：开始你的第一个故事

配置模型

导入和浏览资料可以先做；生成故事、解析内容和与助手对话需要可用模型。

准备连接信息

从你使用的模型服务取得以下信息：

信息含义
Base URL服务的 API 地址，按服务提供的接入说明填写
API Key调用凭证；使用不要求密钥的本地连接时按界面提示处理
模型服务提供的模型名称，需要填写准确的标识

添加并测试

  1. 打开「设置 → 模型配置」。
  2. 在「模型连接」中点击「添加」。
  3. 填写 Base URL 和 API Key，获取模型列表并选择模型；服务不返回列表时，可以手动填写模型名称。
  4. 点击「测试」。测试针对当前填写的信息，不必先保存。
  5. 查看各项结果，再点击「保存连接」。

待补截图：添加模型连接对话框，标出地址、密钥、模型、测试和保存位置；截图时隐藏密钥。

测试会检查基础文本生成、结构化 JSON 输出和无工具单轮 Agent。它帮助判断连接是否适合不同用途，并不代表已经验证了所有角色卡、工具调用和长篇生成场景。

修改地址、密钥或模型后，原来的测试结果不再代表当前信息，应重新测试。

设置实际使用的模型

保存连接后，继续在同一页选择「兜底模型」。助手选择「使用兜底模型」时，会使用这里的连接。

也可以在「角色模型分配」中分别指定：

  • 基本助手：故事解析、状态与记忆相关处理。
  • 写手助手：正文生成与润色。
  • 小精灵：问答、建议与设定检查。

第一次使用可以先选择一个连接作为兜底模型，其他角色保持使用兜底模型。之后有需要再分配不同连接。

待补截图：兜底模型和角色模型分配区域。

确认配置完成

连接应处于启用状态，模型分配应指向你准备使用的连接。列表中的「未测试」「部分可用」「测试失败」需要结合测试明细理解，不能只看连接已经保存。

无法取得模型列表时先检查地址和凭证；能取得列表但生成失败时，查看具体测试错误和对应助手的模型分配。不要通过反复更换角色卡排查连接问题。

导入角色卡

选择文件

  1. 进入「角色卡」，点击「导入角色卡」。
  2. 选择卡片文件。当前导入界面支持 SillyTavern PNG、WebP、JPEG、JSON 角色卡，也支持 Markdown 世界书。
  3. 检查导入选项，确认后导入。
  4. 导入成功后查看自动打开的角色卡详情。

普通图片不一定包含角色卡数据。只有图片外观而没有角色卡信息的文件，不能当作完整角色卡使用。

待补截图：角色卡导入对话框及文件类型、自动解析故事、全局世界书选项。

两个导入选项

自动解析故事决定是否在导入完成后启动故事解析。勾选后，角色卡详情中会显示解析进度；未勾选时，可以稍后从「故事解析」入口启动。

设置成全局世界书使这张卡的世界书词条可以参与其他角色卡的世界书匹配。如果只想正常游玩一张卡，可以先不勾选。

Markdown 世界书走资料导入流程，不能把它与一张包含人物、开场和扩展的完整角色卡等同。

查看角色卡详情

确认卡片名称与介绍，阅读默认开场；有多个开场时切换查看，选择本次想体验的一种。查看是否有已有会话，避免把“继续之前的一局”误当成“重新开局”。

待补截图：角色卡详情，标出开场切换、主角选择、创建新会话、历史会话和故事解析。

故事解析需要等待吗

当前可以在故事解析尚未完成、正在进行或失败时先开局。解析完成后，后续写作会使用相应的增强信息。解析未完成不等于角色卡没有导入成功。

如果解析失败，可先查看详情中的失败说明，检查模型配置后再重试。游玩中发现设定表达有问题，也可以进入世界书检查原始词条。

开始第一次游玩

创建新会话

  1. 在「角色卡」中打开一张卡的详情。
  2. 切换并阅读开场白，停留在准备采用的开场。
  3. 在「新开局」区域选择主角。
  4. 点击「创建新会话」，进入故事。

主角模板决定你在故事中的身份。暂时没有自定义模板时，可以使用已有模板；希望固定姓名和背景时，先去「设置 → 主角模板」复制或新建模板并保存。

故事解析尚未完成时可以先开局。若创建失败，应查看界面返回的具体错误。

待补截图：角色卡详情的新开局区域，显示当前开场、主角选择和创建按钮。

检查写手

进入故事后，查看输入区域的写手选择，使用一个适合本次游玩的写手。写手提供表达和叙事要求；模型连接在设置中管理，两者分开配置。

第一次游玩可以先使用已有写手，完成一轮后再尝试调整文风。

发送第一条行动

在底部输入框描述主角要做什么。例如：

我走到柜台前，压低声音问老板：“昨晚住在二楼的人离开了吗？”

也可以明确一条叙事要求：

我先观察大厅里的旅客，暂时不暴露自己的身份。
（这一轮先描写环境和人物反应，不要替我决定下一步行动。）

检查内容后点击发送，或使用当前设置的发送快捷键。等待本轮生成完成，再阅读新章节与状态变化。

待补截图：故事界面的输入框、写手选择、发送按钮，以及完成后的一章正文。

继续与返回

根据新章节继续输入行动。对结果不满意时，可以使用章节上的撤回或重写操作；只想改善阅读表达时，可以使用润色。它们影响的内容不同，操作前阅读提示。

离开故事页面后，可从角色卡详情的历史会话返回，也可以使用故事顶栏的会话选择继续已有会话。不要为继续游玩再次点击「创建新会话」。

第一次游玩完成后

确认自己已经完成：配置模型、导入卡片、选定主角和开场、创建会话、得到一次正文回应。之后可以从手册目录继续学习指令、右侧栏和写手。

三、进阶游玩：掌握 Play 界面

输入、快捷插入与语义命令

故事区底部的输入框可以直接写下一步行动、对白或叙事方向。你也可以使用 /、@、# 打开快捷插入菜单，把常用表达、角色和提示词放进当前输入中。

普通输入

直接输入自然语言即可。例如：

我先观察门上的刻痕，再询问守门人这里最近发生了什么。

括号中的写作要求会在输入框下方显示为“对系统”提示。它们仍然属于本轮输入的一部分，适合写节奏、视角、篇幅或必须出现的细节：

（保持第三人称限知视角，结尾停在角色做出选择之前）我走向石门。

输入框下方出现的标签只是对本轮输入的即时解析预览，不会替换你实际发送的原文。

待补截图：故事区底部输入框，以及输入要求解析标签的位置。

/：语义命令

输入 /，或点击输入工具栏中的“语义命令”按钮，可以选择以下命令。选中后只会把命令文本插入输入框，不会自动发送。

命令用途
/say明确表示一段对白
/think明确表示角色内心
/act明确表示动作或旁白
/desc/act 的兼容别名，同样用于旁白或动作
/direct以导演要求的方式说明本轮写作意图
/scene提供场景方向或场景变化要求

例如：

/say “你终于来了。”
/think 我不确定他是否已经发现真相。
/act 推开半掩的窗户。
/direct 让这一轮先处理冲突，不要马上解决。

命令可以和普通文字混合输入。发送后，正文区会保留用户消息原文，并在展示时用标签区分命令段落。

@：提及角色或世界书

输入 @ 后，菜单会列出当前状态中可用的角色、主角、世界书词条名和世界书关键词。继续输入文字可以过滤候选，选中后会插入 @名称。

角色候选会按“在场角色”和“已识别角色”分组；世界书候选会显示词条标题或关键词。提及只是告诉本轮写作你想关注谁或哪条资料，是否最终进入提示词仍取决于当前故事的资料检索与注入规则。

@艾琳 请让她先观察桌上的信。
@王城 这次只引用与城内戒严有关的设定。

如果同名角色和词条产生重复候选，菜单会按插入文本去重，角色候选优先保留。

#：快速提示词

输入 # 后可以选择设置中维护的快速提示词。候选显示名称、分组和正文预览，选中后会把完整正文插入输入框；它不会建立新的资源，也不会自动发送。

快速提示词适合保存重复使用的短要求，例如“放慢节奏”“只写角色回应”“检查上一段的因果关系”。管理入口是“设置 → 快速提示词”。如果菜单为空，输入框会提供前往该设置页的入口。

发送方式

  • 点击发送按钮，或使用当前输入快捷键发送。
  • 工具栏的“Enter 发送 / Shift+Enter 发送”按钮可以直接切换模式。
  • 也可以在“设置 → 其他”中调整发送快捷键。
  • 输入框中按换行输入多段内容时，换行会作为同一条用户消息发送。
  • “继续”按钮会发送一条“继续”指令，让写手接着当前情节推进。

生成进行中输入框会暂时锁定。完成、取消或失败后，输入框恢复可用。

工具栏中的其他入口

  • 书本图标：打开当前故事的世界书浏览页。
  • 命令图标：打开 / 语义命令菜单。
  • 向上箭头：滚动到正文顶部。
  • 向下箭头：滚动到最新内容。
  • 当前发送快捷键按钮：切换 Enter 与 Shift+Enter 的发送行为。

待补截图：输入工具栏中世界书、语义命令、滚动和发送快捷键按钮。

输入示例

可以把多个意图写在一条消息里，保持每段目的清楚：

/scene 雨停后的港口
@艾琳 让她注意到守卫袖口上的银线
/direct 先通过对话透露线索，不要直接揭示幕后人物
（保持紧张但克制的节奏，结尾留下一个可追问的细节）

如果你只是想自然推进，直接写普通文字通常更简单；只有需要明确区分对白、内心、动作或导演要求时，才使用语义命令。

生成、重试、撤回与章节润色

每次发送输入后，故事区会显示写作阶段和运行记录。正文完成后，消息底部会出现本轮的用量、耗时和章节操作。

生成中的操作

生成时，输入框右侧会显示当前阶段，例如准备、写作、校验或保存。若当前阶段允许取消，会出现停止按钮“取消本次写作”。点击后等待界面完成取消处理，不要连续点击。

取消只作用于当前这次写作。已经保存的旧章节不会因为关闭右栏或离开页面而被删除。

生成失败后的重试

如果本轮没有完成，正文区会显示“写作未完成”，并提供两个入口：

  • 重试：用原来的输入重新生成本回合。
  • 编辑后重试：把原输入放回输入框，修改后再生成。

失败卡片中的“查看运行详情”可以展开本次运行记录，便于判断是模型连接、写作阶段还是保存阶段失败。

重试前先确认当前仍在正确的故事和会话中。编辑后重试只改变这次重新发送的输入，不会改写已经完成的更早章节。

查看章节正文

每条已完成的助手消息可以选择展示方式：

  • 显示渲染：按故事阅读界面展示正文，适合正常阅读。
  • 显示原文：查看本章实际保存的 LLM 原文，包括协议块或原始标记。
  • 显示润色：在存在有效润色稿时查看独立润色版本。

原文是章节内容的基础；渲染和润色是阅读展示方式。修改原文后，基于旧原文的润色稿会被视为过期，建议重新润色。

编辑正文

点击章节底部的“编辑正文”，可以直接修改本章 LLM 原文。保存后，界面会刷新展示并重新计算本章状态。

编辑正文不会自动重新总结、更新 State Core 或重算后续章节。需要同步历史总结时，打开右栏“历史总结”，找到对应章节后明确点击“编辑总结”或“重新总结”；需要处理 MVU 对历史章节的状态变化时，打开“状态栏”中的 MVU“检查”，按检查结果选择章节并应用补算计划。右栏“状态”的编辑/保存只修改当前状态快照，不会代替历史总结或 MVU 补算。

待补截图：章节底部“显示渲染 / 显示原文 / 润色 / 编辑正文”操作菜单。

撤回并重新生成最新章节

最新章节会常显“撤回本章”操作。确认后，系统会删除最新章节并回滚它对应的状态，再把该轮原提示词放回输入框。你可以直接修改后发送，或保持原样重新生成。

如果输入框中已经有未发送内容，确认对话框会提示覆盖风险；先复制需要保留的文字，再决定是否继续。

撤回只针对最新一章。需要修改更早章节时，先按时间顺序处理后续章节，避免让故事顺序和状态链脱节。

章节润色

在消息的展示菜单中选择“润色…”，可以为当前章节单独生成阅读润色稿：

  1. 选择本次润色使用的写手。
  2. 可选填写润色要求，例如“减少重复形容词，保留对白内容”。
  3. 点击“开始润色”。任务在后台执行，可在任务中心查看进度、失败信息和结果；等待时可以继续阅读、切换页面或写作。

润色稿单独保存，只用于阅读展示。它不会替换章节原文，不参与状态、历史总结或后续写作，也不会改变会话当前使用的写手。重新润色会覆盖本章已有的润色稿。

如果原文章节后来被编辑，旧润色稿会显示为过期；重新润色后才能再次选择“显示润色”。

也可以勾选“同时生成写手改进提案”。此时润色要求必填，既作为润色要求，也作为改进依据；任务会同时产生润色稿和提案。内置核心写手不可修改，不能生成改进提案，但仍可用于单独润色。

根据章节改进写手

在章节操作菜单选择“改进写手…”，选择写手并填写对正文的评价。可以参考整章，或先在渲染／润色视图中选中一段正文，再发起改进。提交后任务在后台执行，可在任务中心查看结果。

改进只生成提案，不修改章节正文，也不生成润色稿。在任务结果中检查提案，确认应用后才会更新所选写手；也可以拒绝提案。所选写手只用于本次操作，不改变会话当前写手。内置核心写手不可修改，请选择其他写手。

会话选择器

从章节创建分支会话

在已完成章节的操作菜单中选择“从本章分支”，确认后会创建并进入新会话。选择第 N 章时，新会话复制到第 N 章为止的内容、状态和历史，从第 N+1 章继续写作；原会话保持不变。写作进行中请先等待当前写作结束，再创建分支。

打开和收起右侧栏

故事区顶部右侧有右栏开关。右栏收起时，正文区域会获得更多宽度；再次点击即可展开。

展开后的右栏顶部是 Tab 区和“＋”按钮：

  1. 点击“＋”查看当前故事可用的扩展。
  2. 点击扩展卡片打开一个 Tab。
  3. 点击 Tab 名称切换内容。
  4. 点击 Tab 上的关闭按钮只关闭视图，不删除故事资料。

桌面端可以拖动正文与右栏之间的分隔线调整宽度；双击分隔线恢复默认宽度。窗口变窄时，右栏宽度会自动限制，以免正文无法使用。

移动端没有固定的桌面三栏布局，右栏内容会以抽屉形式打开。

当前可用的故事扩展

右栏的可用扩展取决于当前故事配置。常见入口包括：

  • 世界书：只读浏览当前角色卡的世界书词条；完整编辑请进入“世界书”主页面。
  • 状态栏：查看角色卡提供的状态栏、MVU 或状态展示；具体内容由角色卡和故事配置决定。
  • 状态：查看 Loresis 当前会话的状态快照，例如场景和角色状态。
  • 历史总结：查看每章摘要、区间摘要和正文 fallback 状态。
  • 设定：编辑只属于当前会话的补充设定和行为/关系备注。
  • 小精灵：在当前故事中提问、查询设定或管理小精灵会话。

有些旧版本保存过的面板不会再出现在“＋”菜单中。当前“记忆”“写作”“写作调试”不是可打开的故事扩展，不要把它们作为现行入口寻找。

右栏状态与会话保存

  • “提交”会将内容作为新的故事输入发送。

如果只是想引用状态或设定，优先使用“填入”，确认内容和语气后再发送。

状态、MVU、历史总结与会话设定

故事区右栏中的几个面板用途不同。先区分它们保存的内容，再决定在哪里修改，能减少“改了却没有生效”的情况。

“状态”：Loresis 当前状态快照

打开右栏的“状态”，可以查看当前会话的结构化状态投影，通常包括：

  • 当前场景的时间、地点、摘要和情境标签；
  • 已识别角色的状态、位置、情绪和关系；
  • 角色的额外字段和主角信息。

点击“编辑”后可以修改这份会话状态，保存后成为后续写作可读取的当前事实。它适合修正已经确认的剧情事实，例如角色位置写错、场景时间需要调整。

状态面板的“刷新”只重新读取当前数据，不会自动从整段正文推断新事实。

待补截图：右栏“状态”面板中的场景和角色状态区域。

“状态栏”：角色卡的展示与 MVU

“状态栏”读取角色卡或故事配置提供的展示能力：

  • 原生状态栏可能直接显示角色卡设计的状态表；
  • sillytavern-mvu 表示角色卡使用了酒馆 MVU 变量；
  • 其他状态展示可能以角色卡提供的 HTML/脚本结果呈现。

如果角色卡没有状态栏，面板会明确显示“当前故事没有状态栏”。这不代表“状态”面板不可用，两者是不同的数据来源。

当面板显示 MVU 时，可使用：

  • 编辑：编辑酒馆变量的原始数据；
  • 检查：重新读取历史章节，检查是否遗漏状态变化并制定补算计划；
  • 刷新：重新加载当前状态栏和状态；
  • 执行保存的开场变量：只在开场 MVU 尚未决定且界面提供该按钮时使用。

“检查”产生的是审阅和补算流程。先查看识别到的变化，再决定是否应用，不要把一次检查当成自动修改正文。

待补截图：sillytavern-mvu 面板的“编辑 / 检查 / 刷新”按钮。

“历史总结”：供后续写作读取的章节摘要

历史总结面板按章节显示摘要。每项可能是：

  • 单章摘要；
  • 最近若干章保留的原文；
  • 跨章节的区间摘要；
  • 没有可靠摘要时的正文 fallback。

可用操作包括：

  • 编辑已有摘要；
  • 重新总结单章；
  • 标记某章固定使用原文；
  • 调整“历史原文章节数”；
  • “补齐并压缩”，补齐缺失总结并按 20 章生成区间摘要。

这里的“使用原文”是后续写作上下文选择，不是把原文改写成摘要。修改摘要不会修改章节正文。

“设定”：本局专属补充

“设定”面板保存只属于当前会话的内容，不修改角色卡和全局世界书。它分为两类：

  • 本局补充设定（Overlay）：用于补充当前局的世界、规则或事实；可以设置作用对象、启用和锁定。
  • 行为/关系备注（Narrative Notes）：记录角色行为倾向、关系变化或本局叙事备注；可以设置优先级、启用和锁定。

编辑后点击“保存”。如果只是想暂时试写一条要求，也可以直接放进故事输入框，不必把它保存成长期会话设定。

四、高阶游玩：控制模型如何写

写手：从酒馆预设到可复用写作方式

写手决定模型如何组织一轮叙事。它与角色卡、世界书和本轮输入分工不同：角色卡提供角色与场景，世界书提供设定资料，写手提供写作方式。

进入写手页

从左侧主导航打开“写手”。左侧列出正式写手，右侧编辑当前选中的写手。列表中的标签可以帮助区分：

  • 单步：写手卡片格式，适合一次调用完成一轮写作；
  • Agent：由身份、演绎规则和文风指导三个槽位组成，适合按步骤组织写作；
  • 核心：内置资源分类。能否编辑与能否删除分别控制，查看锁定标记、编辑控件和删除入口，不要只根据“核心”标签判断。

当前内置“默认写手”是核心、锁定且不可删除：可以预览，不能直接编辑或覆盖保存。示例“基础多步写手”属于可编辑但不可删除的 Agent 写手范文；它不是锁定资源，可以直接修改并保存。普通用户写手通常既可编辑也可删除。

旧版写手仅保留原有数据，不能用于写作或设为默认，也不能在当前写手页编辑或复制。需要继续使用旧内容时，请从原始资源或预设中重新导入，再创建当前支持格式的写手。

待补截图：写手页左侧列表和单步/Agent 标签。

新建、复制和设为默认

  • 点击“新建”，选择创建单步写手或 Agent 写手。
  • 点击“复制”，把当前写手复制成独立的用户写手，再修改副本。
  • 点击星标“设为默认”，让新会话优先使用该写手。
  • 锁定写手可以预览，但保存按钮和编辑控件会被禁用；复制当前写手会创建独立的、可编辑的用户副本。

复制是独立副本。之后修改副本不会回写原写手。

导入酒馆预设

“导入预设”不是直接创建写手，而是把酒馆预设拆成可挑选的资源片段。完整流程如下：

  1. 在写手页的操作菜单中选择“导入预设”，上传 SillyTavern Chat Completion Prompt Manager 的 JSON 预设。一次可以选择多个文件。
  2. 导入后系统会创建后台“预设提取”任务。任务中心会显示排队、进行中或失败状态；普通故事正文生成不会出现在这里。
  3. 点击左侧任务入口打开任务中心，等待该任务变成“待审阅”。点击任务后会打开“预设提取结果”审阅框。
  4. 在审阅框中勾选需要的片段，修改片段名称和分类；未分类条目需要先选择目标分类。可以填写文件名前缀，然后点击“保存到资源仓”。
  5. 保存成功后，选中的内容会成为资源仓中的提示词片段。它们可能位于“写手提示词/灵魂”“写手提示词/文风”“写手提示词/思维链”“写手提示词/特写”“写手提示词/其他”，也可能被归入“世界提示词”或“参考资料”。此时仍然没有创建正式写手。

酒馆预设可能包含平台协议、模板变量或与当前故事无关的块。先在审阅框中取消不需要的片段；不要把整份预设未经检查地当成写作偏好。

待补截图：写手页“导入预设”入口、任务中心中的“待审阅”任务和“预设提取结果”审阅框。

从资源片段创建正式写手

要让提取出的片段出现在故事的写手选择器中，还需要把它们整理成一个正式写手：

  1. 在写手页右侧打开“资源列表”，搜索刚保存的资源。点击资源名称可以预览全文，点击复制按钮可以复制正文。
  2. 点击写手页“新建” → “单步写手”。系统会创建一个可编辑的写手卡片。
  3. 在“灵魂”“文风”“思维链”“特写”“字数与输出偏好”“参考资料”或“其他”分组中新增卡片，把复制的资源正文粘贴到合适的卡片；可以按需要拆成多张卡片。
  4. 点击“保存”，在保存前预览中检查“写手卡片”和“实际注入预览”，确认后保存当前版本。
  5. 回到故事区，点击输入框工具栏中的写作方式按钮，在写手列表中选择刚保存的写手。下一次发送时会使用它。

“世界提示词/世界背景”“主角与角色”“世界规则与能力体系”等片段更适合作为世界资料继续留在资源仓，或整理进角色卡世界书；它们不会因为导入预设而自动变成写手卡片。保存到资源仓和创建正式写手是两个独立步骤。

编辑单步写手

单步写手使用写手卡片组织内容。常见分组包括：

  • 灵魂：写手的定位、立场、擅长题材与创作原则；
  • 文风：视角、句式、节奏、描写密度和对白习惯；
  • 思维链：这里写可执行的写作步骤和检查规则，不是模型的隐藏思考过程；
  • 特写：对对白、动作、心理、场景或镜头的专项偏好；
  • 字数与输出偏好：篇幅、段落长度、对话比例和推进速度；
  • 参考资料：供借鉴的结构、手法或样例；
  • 其他：禁用词、标点和其他补充规则。

每个分组可以新增多张卡片，并通过分类下拉、上移、下移和删除调整结构。保存前建议点“预览”，在“实际注入预览”中检查平台最终拼出的提示词。

写作平台会统一处理最终输出契约、协议区和审计结构。不要把这些平台协议重复粘贴到自己的写手卡片里。

编辑 Agent 写手

Agent 写手在编辑区分别填写三个槽位：

  • 身份：写手的身份和创作目标；
  • 演绎规则：人物动机、场景推进、信息揭示和写作步骤；
  • 文风指导：视角、语言风格和表达偏好。

故事区输入栏旁的写作方式按钮会显示当前选择，例如“某写手·Agent”或“某写手·单步”。发送下一轮时才会使用刚选中的写手。

写手小精灵与提案

写手页右侧“＋”菜单中的“写手小精灵”仅支持单步写手，可以通过对话帮助规划写手身份、文风和自检规则，也可以检索资料库提出修改。三槽 Agent 写手请直接在编辑区修改。

小精灵给出的修改会进入提案看板。查看提案内容后，明确应用才会写回写手；聊天回复本身不会自动覆盖编辑区。对于锁定写手，先复制成可编辑副本。

写手资源列表

右侧“资源列表”可以搜索写手提示词和参考资料：

  • 点击资源名称预览完整正文；
  • 点击复制按钮把正文复制到剪贴板；
  • 资源复制出来后可以作为当前写手卡片的起点，但不会和资源仓建立实时同步。

在故事中切换写手

进入故事后，输入框工具栏的写作方式按钮会打开可用写手列表。选择后，当前会话会记录新的写手选择；下一次发送时生效。生成进行中不能切换写手。

润色对话框也可以单独选择写手，但那只作用于本次章节润色，不改变会话当前使用的写手。

世界书、全局世界书与全局提示词

这三个入口都能影响模型看到的内容，但作用范围不同。先确定你要影响“一张角色卡”“当前会话”还是“多个 LLM 任务”，再选择入口。

当前角色卡的世界书

从角色卡详情或故事区输入工具栏的书本图标进入世界书。左侧选择词条，右侧查看或编辑正文。

每个词条可以设置：

  • 标题和正文；
  • 启用状态；
  • 注入方式；
  • 关键词；
  • 注入位置。
蓝灯与绿灯
  • 蓝灯：每轮强制注入，忽略关键词。
  • 绿灯：只有关键词命中时才注入。

蓝灯开启时，关键词输入框会弱化，因为关键词不会决定这一条是否进入本轮。绿灯词条需要同时启用，并且在当前检索文本中命中关键词才有机会注入。

“启用”是词条自己的开关。当前故事没有另设一个故事级世界书总开关；需要停用某条资料时，在词条列表中关闭它。

故事解析中的启用内容

世界书的“故事解析”页会显示当前故事解析使用哪些内容，并提供两个独立的启用开关，同时列出世界书词条的使用情况：

  • 故事解析：是否在写作时使用故事基调与演绎规则；
  • 世界书词条：这里是当前已启用词条的入口和数量提示，不是另一个总开关；具体启用状态仍在词条列表中逐条控制；
  • 状态栏：是否使用角色卡原有状态栏、MVU 或展示能力。

修改角色卡或世界书后，可以点击“重新构建故事解析”覆盖当前解析结果。解析失败或尚未构建时仍可以先开局；解析属于写作增强，页面会显示当前状态和失败原因。

全局世界书

在角色卡详情的“全局世界书”开关可以把这张角色卡的世界书挂载为全局资料。开启后，这些词条可以参与其他角色卡的世界书匹配；关闭后会取消挂载，但不会删除角色卡或词条内容。

全局世界书适合放跨故事共享的地点、组织、术语或共同世界观。只对一张卡有效的设定，继续放在该卡自己的世界书中更容易维护。

全局系统提示词

入口是“设置 → 其他”中的“全局系统提示词（非写手）”。这里的文本会注入到除写手任务之外的所有 LLM 系统提示词之前。

因此：

  • 它适合给除写手任务之外的模型调用提供统一的系统级上下文或格式要求；
  • 它不会注入 task.writer.compose 写手请求；
  • 留空并保存即可关闭全局系统提示词；
  • 这不是当前故事的专属设定，也不会替代角色卡世界书。

填写后点击“保存提示词”。页面会显示更新时间和字符计数，最长 20,000 个字符。

查看提示词与控制文风

当模型没有按预期写作时，先查看实际提示词，再决定是改本轮输入、写手、世界书还是全局设置。

打开本轮提示词

在已完成的助手章节底部点击“显示提示词”。开场白没有写作回合时不会提供这个按钮。

弹窗会按记录展示以下内容：

  • 提示词组成：不同输入块的估算占比和 token 数；
  • 缓存用量：提供方返回缓存数据时，查看读写量和调用明细；
  • 高级诊断：资料检索：查看检索输入、角色提及、世界书关键词命中、激活和最终 Prompt 状态；
  • 实际提示词：单步写手显示记录到的完整提示词，Agent 写手显示已记录的写手提示词内容。

Agent 写手可能一轮进行多次调用，因此弹窗会明确提示：记录内容可能只覆盖部分调用，不能把它强行理解为一个完整的单次提示词。

旧记录或未记录资料检索诊断时，相关区域会显示“未记录”，不会替你补造命中结果。关键词命中也不等于最终进入 Source 或参考资料 Prompt，应以最终提示词状态为准。

待补截图：本轮提示词弹窗的“提示词组成、资料检索、实际提示词”三个区域。

先看哪一层

建议按以下顺序检查：

  1. 实际提示词中是否出现了本轮输入和你期待的规则。
  2. 世界书诊断中，词条是未命中、未激活、被预算省略，还是已进入最终 Prompt。
  3. 写手卡片或 Agent Skill 是否真的出现在当前请求中。
  4. 如果来源都已出现，再检查规则之间是否互相冲突或要求过多。

用四种手段控制文风

本轮输入

适合一次性的局部要求，例如：

（本轮使用克制的第三人称限知视角，减少解释性总结，结尾停在敲门声处）

它最接近当前任务，适合测试一个方向是否有效。

写手

适合长期复用的写作方式。把稳定的视角、句式、节奏、对白比例和自检规则放在写手中；不要把只对某个章节成立的剧情事实写进写手。

写手中的“参考资料”是低优先级的风格或手法参考，不应当被当作当前故事事实。

当前角色卡的世界书

适合当前角色卡或当前世界的长期文风与叙事规则。用蓝灯保存每轮都需要遵守的规则，用绿灯保存只在相关关键词出现时注入的局部规则。它只影响这张角色卡的故事，不会自动成为其他角色卡的写作要求。

全局世界书

适合多个角色卡共享的文风或叙事约定，例如统一的时代语气、通用术语写法或共同世界观的表达方式。开启角色卡详情中的“全局世界书”后，这张卡的世界书词条才会参与其他角色卡的世界书匹配；它仍然会按词条的蓝灯/绿灯、启用状态和关键词规则生效。

全局系统提示词的范围

它的范围是除写手任务之外的 LLM 系统提示词，明确不会注入写手请求。需要改变写手风格时，应修改写手、世界书或本轮输入。

一个可复用的调试流程

假设角色总是写得过于华丽：

  1. 先在本轮输入中要求“短句、减少比喻”，确认模型是否能按要求改变。
  2. 如果有效，再把稳定要求整理到写手的“文风”卡片。
  3. 如果所有角色卡都需要同一种表达方式，放进全局世界书；如果只有当前角色卡需要，放进当前角色卡的世界书。
  4. 发送一轮后打开“显示提示词”，确认规则实际进入了请求。
  5. 如果同一规则在多个入口重复出现，删除重复内容，只保留最适合该场景的一处。

不要同时修改四个入口后再观察结果，否则很难判断是哪一处真正起作用。

故事解析与高阶排查

故事解析会把角色卡、世界书和相关资料整理成故事基调与演绎规则，供写作时按当前角色和阶段使用。它是写作增强层，不替代角色卡、世界书或会话状态。

查看故事解析

进入角色卡相关的“世界书”页面，打开“故事解析”页签。这里可以查看：

  • 故事解析是否启用；
  • 当前已启用的世界书词条数量；
  • 状态栏是否启用；
  • 故事基调；
  • 演绎规则库及其分组；
  • 编译警告和冲突。

完整规则库会在写作时按当前角色和阶段投影注入；页面展示的是供你审阅的规则总览，不代表每条规则每轮都会进入提示词。

待补截图：世界书“故事解析”页的启用内容、故事基调和演绎规则库。

重新构建

修改角色卡、世界书或相关资料后，如果希望故事解析反映新内容，点击“重新构建故事解析”。重新构建会覆盖当前解析结果。

构建中页面会显示进度，重复点击不会启动第二个同类任务。构建失败时，页面会保留错误提示，并提供查看任务日志或重试入口。

解析尚未完成或构建失败时仍可以创建会话并开始故事；此时写作不会获得这层解析增强。你可以先开局，之后回到故事解析页重新构建。

解析没有生效时

按下面顺序检查：

  1. 故事解析开关是否打开。
  2. 需要的世界书词条是否单独启用。
  3. 词条是蓝灯常驻还是绿灯关键词触发；绿灯需要在本轮检索文本中命中。
  4. 角色卡或世界书修改后是否重新构建了故事解析。
  5. 在故事区打开一条已完成章节的“显示提示词”，查看故事基调或规则是否进入实际请求。

如果规则已经进入提示词但仍未达到预期，优先减少冲突要求，再分别测试本轮输入、写手和世界书的效果。

世界书词条没有命中时

打开当前故事右栏的“世界书”只能浏览词条，完整设置请进入世界书主页面。检查以下项目：

  • 词条是否启用；
  • 是否误设为绿灯而没有匹配关键词；
  • 关键词是否包含当前输入和上下文中实际出现的表达；
  • 词条是否被检索器选中但最终因预算未进入 Prompt。

“显示提示词”中的“高级诊断：资料检索”会把这些状态分开显示。关键词命中、检索器选中和最终进入 Prompt 是不同结果。

文风修改没有效果时

不要先继续堆叠规则。先打开提示词确认：

  • 当前会话实际选择了哪一个写手；
  • 规则是写在写手、世界书、全局系统提示词还是本轮输入；
  • Agent 写手是否使用了多次调用，当前查看器是否只记录了部分调用；
  • 是否存在互相冲突的“长篇细节”和“短句克制”等要求。

确认来源后只改一个入口，再发送一轮比较。章节润色是阅读展示资产，不能用它判断下一轮写作风格是否已经改变。

状态栏和 MVU 没有变化时

先区分“状态”与“状态栏”：

  • “状态”是 Loresis 当前会话的结构化状态快照；
  • “状态栏”是角色卡提供的状态展示或 MVU 能力。

如果使用 MVU，先在“状态栏”中点击“刷新”查看最新数据；需要检查历史章节遗漏时使用“检查”，查看补算计划后再应用。修改故事正文不会自动重算所有后续章节，涉及历史状态时应在面板中明确执行对应的检查或补算。

需要保留的判断边界

  • 故事解析是派生的写作增强结果，不是角色卡正文的替代品。
  • 提示词查看器展示的是已记录的请求内容；它不能证明没有记录的调用一定没有使用某条规则。
  • 关键词命中不等于最终注入。
  • 润色稿只用于阅读，不会成为下一轮写作上下文。

五、创世入门：按照酒馆角色卡方式创作

创世区：从想法到角色卡草稿

创世区用于从一个空白草稿开始制作原生角色卡。你可以先写角色、世界和开场，再逐步补上世界书、酒馆扩展和互动选项；也可以从已有角色卡详情进入「进行创世编辑」，复制一份草稿继续改。创世区中的修改先属于当前草稿，只有使用「保存成角色卡」后，才会写入角色卡库并进入后续故事流程。

从哪里进入

在左侧主导航选择「创世」。进入后会看到「创世草稿」列表。

  • 选择「新建角色卡草稿」创建空白原生角色卡。
  • 点击某个草稿卡片进入工作台。
  • 草稿卡片可以重命名、复制或删除。
  • 删除的草稿会进入创世区的「回收站」，可以从回收站恢复。

已有角色卡的入口是：打开角色卡详情，点击封面下方的「进行创世编辑」。应用会以这张卡的内容创建一份新的创世草稿，并打开草稿工作台；原来的角色卡不会被直接修改。

待补截图：创世草稿首页，标出「新建角色卡草稿」、草稿卡片操作和「回收站」。

新建与复制的区别

「新建角色卡草稿」会生成一张空白的原生角色卡，名称、描述、人格、场景、开场白和世界书都可以随后填写。

「复制」会把当前草稿复制为另一份草稿，并在名称后加上副本标记。复制适合尝试两个不同方向，例如保留同一角色但分别测试两种开场，或者在同一世界观下制作不同版本。复制不会直接覆盖已有角色卡。

草稿工作台的三个区域

打开草稿后，工作台由三部分组成：

  1. 中间的原生角色卡编辑区：按「角色定义」「世界书」「开场」「酒馆扩展」「互动选项」分栏编辑。
  2. 右侧扩展栏：打开「创世小精灵」「资源列表」或「角色卡预览」。
  3. 顶部操作区：关闭草稿，或选择「保存成角色卡」。更多操作（复制、删除草稿）在自适应操作菜单中。

草稿编辑会自动保存到当前创世草稿。这里的自动保存只代表当前草稿已经记住你的修改；它不等于已经保存为角色卡，也不会自动生成一个可游玩的故事。

建议的创作顺序

可以按以下顺序完成一张卡：

  1. 在「角色定义」中先写名称、角色描述、人格和场景。
  2. 在「世界书」中补充需要按需注入的地点、人物、规则或背景。
  3. 在「开场」中写默认开场，必要时添加备用开场。
  4. 如果故事需要状态、变量、状态栏或文本转换，再到「酒馆扩展」处理 MVU、Helper、Regex 等定义。
  5. 如果希望每轮生成后给出行动建议，到「互动选项」启用并配置槽位。
  6. 用右侧「角色卡预览」检查当前卡片内容，再保存成角色卡。

不用一次完成所有分栏。角色卡可以先保存一个可玩的版本，之后再回到创世草稿继续调整并再次保存。

草稿与角色卡的边界

以下操作只修改草稿：编辑字段、添加或删除世界书词条、修改开场、编辑酒馆扩展、配置互动选项、让创世小精灵修改内容，以及把资源列表中的内容添加到当前世界书。资源列表中打开已有资源并编辑后点击保存，会修改资源仓中的原文；它不属于草稿自动保存。

「保存成角色卡」才会把草稿写入角色卡库。保存对话框提供两种目标：

  • 「另存为新的角色卡」：输入新名称，创建一张新卡。
  • 「覆盖」：从已有角色卡列表中选择目标，写回选定卡片。

保存成功后，应用会跳转到角色卡详情，并尝试启动故事解析。故事解析和草稿保存是两件事：解析可以继续进行、稍后重试或重新运行，角色卡仍然已经保存。

暂时不需要模型也能做什么

创建草稿、手动编辑原生字段、世界书和扩展，以及浏览资源，不需要先让创世小精灵生成内容。调用创世小精灵、使用 AI 修改或执行需要模型的助手操作时，才需要先在「设置 → 模型配置」完成可用模型连接。

原生角色卡字段

创世区直接编辑一份原生角色卡草稿。常用字段在界面中展开编辑；暂未单独展示的字段仍可通过「完整原生角色卡 JSON」查看和修改。

角色定义分栏

「角色定义」中包含这些常用字段：

  • 名称：角色卡名称，也是保存为新卡时的默认名称。
  • 人格：角色稳定的性格、价值观、习惯和表达倾向。
  • 标签：用逗号分隔的标签，便于整理和检索。
  • 创作者：角色卡署名或来源说明。
  • 角色卡版本：用于记录你自己的版本信息。
  • 角色描述：角色、故事或体验的主要内容。它不必局限于单一人物，也可以描述一个群体或一段事件。
  • 场景：开场时的地点、时间、处境和正在发生的事情。
  • 示例对话：展示希望角色怎样说话、怎样回应用户。
  • 创作者备注：给使用者或未来的自己看的补充说明。
  • 系统提示词：角色卡自带的系统层要求。
  • 历史后指令：放在历史对话之后的补充指令。

没有必要把同一段内容复制到每个字段。建议把长期事实放在描述、人格、场景或世界书中，把第一幕的具体行动留给开场。

待补截图：角色定义分栏，标出名称、人格、角色描述、场景、系统提示词和历史后指令。

让字段更容易被使用

角色描述适合回答“这张卡的核心体验是什么”；人格适合回答“角色如何思考和说话”；场景适合回答“故事从什么时刻开始”。如果一段文字同时承担多个作用，可以拆到两个字段，而不是把所有内容堆进系统提示词。

示例对话不是必须项。它更适合用来固定称呼、语气、句式和互动节奏；如果角色的说话方式已经在人格或写手中写得足够清楚，可以留空。

完整原生角色卡 JSON

在「酒馆扩展」分栏下方可以展开「完整原生角色卡 JSON」。这里用于编辑没有在界面中单独展开的原生字段，也可以检查卡片的整体结构。

使用时注意：

  1. 必须输入合法 JSON。
  2. 未在页面中展开的未知字段会原样保留，不要为了“整理格式”随意删除它们。
  3. 角色定义、世界书、开场和酒馆扩展在界面中有专门编辑器，优先使用专门编辑器；JSON 更适合检查或处理特殊字段。
  4. 输入框失焦后应用会尝试应用 JSON。若格式不合法，页面会保留错误提示，保存成角色卡前需要先修正。

AI 修改也遵守同一边界：创世小精灵修改的是当前草稿中的原生卡片，不会直接替你保存到角色卡库。

自动保存与手动检查

普通字段修改后，草稿会在短暂延迟后自动写入。切换分栏前不需要逐项点击保存，但在点击「保存成角色卡」前，应用会先等待尚未完成的草稿写入，并检查原生 JSON、酒馆扩展编辑器和互动选项中的未保存内容。

如果保存对话框提示无法保存，先回到对应分栏查看错误提示。最常见原因是完整 JSON 不合法，或某个扩展编辑仍处于未完成状态。

保留原生结构

创世区不是把角色卡转换成另一种自定义格式。保存时会保留原生角色卡的标准字段、世界书、开场、扩展和未知字段；页面只是为常见内容提供更容易操作的编辑入口。

世界书、开场与互动选项

这三个分栏分别解决三个问题：故事需要记住哪些设定、故事从哪里开始、每次生成后是否给用户几个明确的下一步方向。

世界书词条

在「世界书」分栏可以添加、编辑和删除词条。每个词条包含标题、正文、启用状态、注入方式和关键词；还可以填写分类或其他设置 JSON 作为辅助信息。

蓝灯与绿灯
  • 蓝灯（常驻）：每轮都注入，不依赖关键词。适合叙事视角、核心世界规则、永远不能忘记的身份关系等内容。
  • 绿灯（关键词）：命中词条关键词时才注入。适合某个地点、势力、物品或只在特定剧情出现的背景。

词条未启用时，即使关键词命中也不会注入。绿灯词条没有关键词或关键词写得过窄时，可能不会被触发；如果一条内容必须每轮可见，使用蓝灯更直接。

待补截图：世界书词条列表，标出启用开关、蓝灯/绿灯开关、关键词和正文编辑区。

如何拆词条

一条词条最好围绕一个可复用事实组织。例如：

标题：旧钟楼
关键词：旧钟楼、钟楼、地下钟室
正文：旧钟楼位于雾港北侧……

把“人物关系”“地点历史”“当前剧情规则”分成不同词条，后续更容易单独启用、修改或让创世小精灵检查。不要因为有很多段落就全部设置为蓝灯；常驻内容越多，每轮提示词越长。

默认开场与备用开场

在「开场」分栏中：

  • 「默认开场白」是进入故事时使用的第一条消息。
  • 「添加备用开场」可以增加不同进入方式，例如不同视角、不同时间点或不同事件起点。
  • 每个备用开场都可以单独编辑和删除。

开场应当给用户留下回应空间。可以交代地点、人物和正在发生的事，但不要把用户的第一步行动完全写死。需要不同玩法时，优先新增一个备用开场，而不是在一段文字里堆叠多个互相冲突的开端。

如果开场中包含 MVU 初始值，酒馆扩展的预览会按当前开场显示对应初始值；修改开场后应重新检查相关状态。

互动选项

「互动选项」不是角色卡原生字段，而是创世草稿的一组写作运行规则。它决定每次写作是否准备若干个“下一步”选项；游玩时，这些选项会显示在助手回复下方，点击后把对应行动送回输入流程。

打开互动选项后需要配置 2～5 个槽位。每个槽位有：

  • id：程序识别用的唯一标识，例如 investigate。
  • 名称：用户看到的简短标签，例如“调查钟楼”。
  • 说明：告诉写作流程这个选项应该引导什么行动或后果。

槽位 id 不能重复，三项都必须填写。可以再添加自然语言规则，例如“每个选项都应代表不同方向的明确行动”，或“至少有一个选项允许用户继续追问人物”。

互动选项适合调查、分支探索和有明确行动方向的故事。如果故事更适合完全自由输入，可以保持关闭；关闭后不会在回复下方显示选项。

待补截图：互动选项分栏，标出启用开关、2/5 槽位计数、槽位 id/名称/说明、规则和保存状态。

与角色卡正文的区别

角色描述、世界书和开场属于角色卡正文或原生结构；互动选项属于创世草稿的运行设置。它们分别由不同的编辑器保存。保存成角色卡时，互动设置会随卡片保存，并在游玩时参与运行，不应把互动规则复制成世界书词条。

酒馆扩展与角色卡预览

创世区保留角色卡中的酒馆扩展。它不会把所有扩展都重新解释成 Loresis 自己的格式，而是按照卡片原有结构展示可识别的 MVU、Zod、Helper 和 Regex 定义。

选择开场后再检查扩展

「酒馆扩展」分栏顶部有开场选择器。默认开场和每个备用开场都可以分别查看。带有开场初始值的开场会显示“含初始值”标记。

先选择要测试的开场，再查看下面的定义。这样能发现“默认开场正常、备用开场没有初始值”这类差异。

MVU 与 Zod

MVU 区域可能包含：

  • 全局 InitVar：通常以世界书词条形式保存初始状态。
  • 当前开场初始值：只属于选中的开场。
  • Zod Schema：以 TavernHelper 脚本形式注册状态结构。
  • MVU 更新规则：说明剧情中哪些变化应更新变量。

可以展开定义查看原文，编辑后保存，也可以切换启用状态。不要只看状态栏是否出现就判断 MVU 完整；初始值、Schema 和更新规则分别承担不同职责。

如果你不确定某个字段该放在哪里，可以让创世小精灵先读取当前 MVU 定义，再按“要记住什么、初始值是什么、什么时候变化、用户需要看到什么”逐项修改。

Helper

Helper 按角色卡原来的命名显示。它可能参与 MVU、状态栏或其他扩展功能，界面不会替你把它归类成某一种用途。编辑前先展开查看脚本内容，并保留它依赖的对象和名称。

Regex

Regex 列表按角色卡原有顺序展示。展开某条 Regex 可以查看：

  • Find Regex
  • Replace String
  • 是否只作用于 Markdown 或 Prompt
  • 是否在编辑时运行
  • 深度、位置、替换字符串等参数

Regex 是否用于状态栏，取决于卡片本身的命名和实际预览结果。不要只根据“Regex”这个类型名判断它的业务用途。修改后应在选定开场上使用预览确认。

新增定义

如果当前卡片允许编辑扩展，可以在「新增」菜单中选择：

  • InitVar
  • MVU 更新规则
  • Zod
  • Helper
  • Regex

新增 Zod 或 Helper 时需要填写名称和脚本原文；新增 Regex 时需要填写查找正则和替换内容等定义。保存前先确认脚本属于当前角色卡，避免把另一张卡的运行规则直接复制过来。

待补截图：酒馆扩展分栏，标出开场选择器、MVU、Zod、Helper、Regex 的展开和编辑入口。

角色卡预览

右侧扩展栏的「角色卡预览」会把当前草稿的主要字段和世界书词条列出来。预览支持搜索，蓝灯和绿灯词条会用不同标记显示。

这份预览用于检查“草稿中目前有哪些内容”，不是游玩时的最终消息渲染。要检查 Regex、HTML 和状态栏是否经过实际展示链，应在「酒馆扩展」中选择开场并使用对应预览，而不是只看预览列表中的原文。

创世小精灵与资源列表

创世小精灵负责围绕当前原生角色卡草稿进行读取、整理和修改。右侧「资源列表」则用于浏览可参考的世界提示词和参考资料。两者都服务于当前草稿，但作用不同：助手可以编辑草稿，资源列表只是选择并复制内容到世界书。

打开创世小精灵

在草稿工作台右侧打开「创世小精灵」。也可以在每个分栏顶部的提示卡中点击「创世小精灵」，让应用把对应的提问示例放入聊天输入区并发送。

助手聊天区支持：

  • 直接描述你的创作想法或修改要求。
  • 输入 / 查看当前可用快捷指令。
  • 点击字段旁的「AI 修改」，把该字段作为本次修改目标。
  • 取消正在进行的请求、清空聊天记录、收起助手。

当你从某个字段点击「AI 修改」后，聊天输入区会显示“正在修改：字段名”。此时写“扩写这一段”“保留事实但改成克制语气”等要求，助手会以该字段为上下文处理。

待补截图：创世小精灵面板，标出字段级「AI 修改」、/ 快捷指令、取消发送和清空聊天记录。

助手能修改什么

助手可以读取和更新当前草稿的原生字段、世界书词条、开场和酒馆扩展，也可以读取 MVU 定义并生成预览检查结果。它的修改会写回当前创世草稿，聊天记录会保留修改记录，方便展开查看修改前后的模块内容。

助手不能绕过保存成角色卡这一步，也不能把创作 Skill 当成新的权限或新的数据源。最终是否保存、保存为新卡还是覆盖已有卡，仍由你在顶部保存对话框中决定。

怎样提问更容易得到可用结果

把“目的、必须保留的事实、希望改变的地方”一次写清楚。例如：

保留雾港、失踪者和旧钟楼这三个事实，把角色描述改成更适合悬疑开场的版本，避免提前揭示凶手。

修改后先查看对应分栏，再继续提出下一步要求。对于 MVU、Regex 或扩展，最好明确说明“保留已有规则，只修改字段 X”，并要求助手先读取当前定义。

资源列表

右侧「资源列表」可以搜索和浏览资源仓中的「世界提示词」与「参考资料」。点击条目可以查看正文；带加号的条目会被添加为当前角色卡的一条世界书词条。

添加后的内容会复制进当前草稿，之后可以在「世界书」分栏中修改标题、正文、蓝绿灯和关键词。它不会与资源仓原文保持实时同步。

资源列表不会直接加载「创世 Skill」。Skill 通过创世助手在资源仓中按需读取；具体用法见「创世 Skill」章节。

待补截图：资源列表搜索、资源预览和“添加到卡片拼装”按钮。

资源正文的独立编辑

打开带路径的资源时，可以编辑资源名称和正文并保存回资源仓。若新建资源时出现同名提示，可以选择覆盖原资源，或让应用生成并存一份名称带序号的副本。当前草稿中已经复制的世界书内容不会因为资源仓原文后来变化而自动更新。

保存角色卡、试玩与继续修改

创世的最后一步不是关闭草稿，而是把当前草稿保存成角色卡。保存后它才会出现在角色卡库中，才能按普通角色卡流程创建故事会话。

保存前检查

点击顶部「保存成角色卡」时，应用会先等待尚未完成的草稿写入，并检查：

  • 完整原生角色卡 JSON 是否合法；
  • 酒馆扩展编辑器是否还有未完成或错误的编辑；
  • 互动选项是否满足槽位和字段要求。

如果保存按钮不可用或出现错误，先回到对应分栏修正内容。不要在错误仍存在时反复点击保存。

另存为新角色卡

保存对话框默认选择「另存为新的角色卡」。输入新角色卡名称，必要时上传或更换封面，然后点击「另存为新角色卡」。

这会创建一张新的角色卡，不改变原有角色卡。适合第一次发布草稿，或想保留原卡并制作一个变体。

覆盖已有角色卡

在「保存方式」下拉框中选择「覆盖：角色卡名称 · 目录」，确认按钮会变成「覆盖角色卡」。确认前应再次检查目标名称，因为这会把当前草稿内容写回该角色卡。

覆盖只针对你选中的目标卡，不会把其他卡片一起修改。需要保留旧版本时，先复制草稿或选择另存为新卡。

封面

保存对话框可以上传封面或更换已有封面。封面会随角色卡一起生成。封面只是角色卡展示内容，不会改变角色定义、世界书或写作规则。

待补截图：保存对话框，标出另存/覆盖选择、新卡名称、封面上传和确认按钮。

保存后的下一步

保存成功后，应用会跳转到角色卡详情，并尝试启动故事解析。解析可以继续进行、稍后重试或重新运行；它没有完成时，只要详情页允许创建会话，就可以先开始一局。

在角色卡详情中，先用开场预览左右切换并选定默认或备用开场，再在「新开局」区域选择主角，点击「创建新会话」。故事解析显示“解析中”、已有草案或失败提示时，详情页仍会展示当前可用的开局入口；如果当前卡片还没有完成创建会话所需的基础准备，页面会提示先处理解析。

进入故事后，再从输入区上方的「写作方式与写手」按钮选择写手。选择会在下一次发送时生效；创建会话时不需要在角色卡详情中先选写手。创世草稿中的“预览”用于制作阶段检查，不能替代进入故事后的真实试玩。

试玩清单

进入故事后，建议至少检查：

  1. 默认开场是否能自然接话。
  2. 备用开场是否都显示正确，尤其是带初始值的开场。
  3. 世界书蓝灯是否持续生效，绿灯是否在关键词出现时生效。
  4. 状态栏、MVU 变量和 Regex 是否按预期显示或更新。
  5. 互动选项是否出现在助手回复下方，选项方向是否真正不同。

发现问题时，回到创世草稿修改原始字段或扩展，再重新保存。已经保存的角色卡不会因为你继续编辑草稿而自动变化，反之亦然。

关闭、删除和恢复草稿

「关闭草稿」只离开当前工作台，不删除草稿。顶部更多操作中的「删除草稿」会把草稿移入创世回收站；在创世首页打开「回收站」可以恢复。删除草稿不会删除已经保存的角色卡。

六、创世进阶：使用与编写创世 Skill

创世 Skill：让助手采用一套创作方法

创世 Skill 是资源仓中供创世小精灵参考的 Markdown 方法资料。它可以描述一套人物塑造、关系设计、冲突推进或开场构思的方法，让助手在处理当前草稿时有更明确的工作步骤。

Skill 是参考材料，不是角色卡正文，也不是新的工具权限。它不能覆盖创世助手的基础规则、替你决定当前草稿内容、跳过用户确认，或自行保存成角色卡。

Skill 与其他资源的区别

  • 角色定义、世界书和开场：属于当前原生角色卡草稿，直接决定卡片内容。
  • 世界提示词、参考资料：是可以浏览并复制到当前卡片的内容素材。
  • 创世 Skill：是助手可以按任务读取的创作方法，通常不直接复制进角色卡。

如果你想让“旧钟楼”的事实出现在故事里，应把它写入角色描述或世界书；如果你想让助手每次设计地点时都先写功能、冲突和感官细节，可以把这套步骤写成 Skill。

创建入口

打开「资源仓」，点击「新建」，选择「创世 Skill」。应用会在「创世 Skill」目录下创建一个可编辑的文本资源。填写名称和正文后保存。

Skill 必须是 Markdown 文本，扩展名为 .md，并位于资源仓顶层的「创世 Skill」目录或其子目录中。只有这个目录下的 Markdown 资源会出现在创世小精灵的 Skill 列表中。

待补截图：资源仓“新建资源”对话框，标出「创世 Skill」入口，以及保存后的目录位置。

Skill 如何被使用

在创世对话中，先告诉助手你希望解决的问题，例如“用关系设计 Skill 检查当前人物冲突”。助手可以列出当前可用 Skill，再读取其中一份正文作为本轮创作方法参考。

Skill 的摘要来自正文的 YAML description；没有描述时，应用会取正文开头的一段作为摘要。因此写一个清楚的 description，比把所有内容塞进文件名更容易查找。

Skill 不是每轮自动注入。助手只有在当前任务需要时才应读取它；如果你希望它采用某个方法，直接在请求中点名 Skill 或说明方法目标。

推荐的 Skill 结构

一个容易复用的 Skill 通常包含：

  1. 适用场景：什么时候使用，什么时候不要使用。
  2. 工作目标：希望最终得到什么结果。
  3. 执行步骤：助手按什么顺序阅读和处理当前草稿。
  4. 检查清单：完成后如何检查重复、矛盾、空泛或缺少行动空间。
  5. 示例：一小段输入与期望输出形态。

方法应该描述“怎么思考和检查”，不要把某一张角色卡的固定事实写成通用规则。固定事实放在角色卡或世界书中。

编写自己的创世 Skill

下面用“人物关系检查”示例说明如何把一套创作经验写成可复用 Skill。示例只提供方法，不绑定某个角色、地点或故事。

第一步：确定一个窄目标

不要写“让角色更精彩”这种无法检查的目标。先限定一个具体任务，例如：

检查当前角色卡中的两名关键人物是否拥有不同目标、可见分歧和下一步行动空间。

这个目标可以应用于悬疑、冒险、恋爱或群像故事，但不会替用户决定人物事实。

第二步：写入 Skill 正文

在资源仓中选择「新建 → 创世 Skill」，名称可以填写“人物关系检查”。正文可以这样写：

---
description: 检查角色卡中的关键人物关系是否有目标差异、可见分歧和后续行动空间。
---

# 人物关系检查

## 适用场景

当角色卡包含两名或更多关键人物，且需要检查关系是否能推动剧情时使用。

## 工作目标

在不新增未经用户确认的事实前，找出关系中已经存在的目标、分歧和可行动空间；缺失部分以问题形式反馈。

## 执行步骤

1. 先读取当前角色定义、场景和相关世界书词条。
2. 为每名关键人物列出：当前目标、担心失去的东西、对另一人的期待。
3. 对比双方目标，标出相同点、冲突点和还没有证据的推断。
4. 检查开场是否让用户能够看见至少一个关系张力。
5. 给出两到三个可以在开场后自然发生的行动方向，但不要替用户选定结果。

## 检查清单

- 是否把角色卡已有事实和助手推测分开？
- 两名人物是否真的有不同目标，而不是只有不同形容词？
- 分歧是否能在场景或对白中被看见？
- 建议的行动是否保留用户回应空间？
- 是否重复了已经存在的世界书内容？

## 输出格式

先给“已确认事实”，再给“关系缺口”，最后给“可选的下一步行动”。除非用户明确要求，不要直接覆盖角色卡字段。

保存后，回到创世草稿，在创世小精灵中提出：“请读取人物关系检查 Skill，按它检查当前角色卡。”

第三步：检查助手是否真正采用了方法

有效的结果应当体现 Skill 中的顺序和检查标准，例如先列出已确认事实，再指出关系缺口，而不是直接替你重写角色卡。你可以继续追问：

  • “你刚才哪些结论来自角色卡，哪些只是推测？”
  • “按照检查清单，开场还缺什么？”
  • “只给出行动选项，不修改字段。”

如果结果没有遵循方法，先检查 Skill 是否位于「创世 Skill」目录、文件是否为 .md，再在请求中明确点名它。Skill 不会自动成为每一轮对话的永久系统提示词。

编写时应避免的内容

  • 不要在 Skill 中写入 API、脚本或要求助手执行终端命令。
  • 不要把“必须覆盖保存”“必须启用某个扩展”等产品操作写成创作方法。
  • 不要假定 Skill 可以修改权限、工具列表或保存边界。
  • 不要把当前角色的具体姓名、世界规则和唯一剧情事实写成通用模板，除非这份 Skill 就是只供该项目使用的内部方法。

Skill 的价值在于让创作过程可重复、可检查。角色卡内容仍然由你确认，助手的修改也仍然先落在当前草稿中。

角色卡与资源仓管理

查找角色卡与继续会话

进入「角色卡」，在顶部搜索框输入卡片名称或目录名。页面提供「快捷入口」「角色卡库」「历史会话」定位入口。

点击卡片打开详情，查看介绍、开场和已有会话。想继续之前的剧情时，选择历史会话；想尝试另一条路线时，选择开场和主角后创建新会话。

在详情的会话列表中，可以编辑会话名。使用能辨认路线的名字，例如「调查员·先去码头」，比多个相同名字更容易区分。

管理封面

在角色卡详情中，没有封面时使用「添加封面」，已有封面时使用「调整封面」。根据封面编辑对话框选择图片并调整裁切，确认保存后检查详情中的效果。

封面操作改变展示图片，不用于编辑人物设定或开场内容。

删除前确认范围

删除会话会移除该会话的章节、状态和聊天记录。删除角色卡的范围更大，确认框会说明它将同时移除角色卡及其所有会话等内容。

删除与从列表中退出不同。只想离开一局时，切换页面或会话即可。

使用资源仓

资源仓用于保存和查找可复用材料。进入后，先选择左侧分类，再用搜索框缩小范围，选中资源查看内容。

  1. 点击「新建」创建资源，按用途选择资源类型和保存位置。
  2. 已有文件可以使用「上传资料」。
  3. 选中资源后检查名称、类型和正文，再使用当前编辑区域提供的保存操作。
  4. 需要复用时，在创世或写手的资源面板找到对应材料，按该面板提供的操作引用或复制。

待补截图：资源仓分类、搜索、资源列表、编辑正文和新建入口。

“放进资源仓”不等于“每轮自动注入”。创世 Skill、参考资料、写手提示词和世界书词条的用途不同。用于故事固定设定的内容，应在相应世界书中配置；用于创作方法的材料，可作为创世 Skill。

批量整理时，「多选编辑」可以选择多项资源。删除前检查所选列表；不要用删除资源来代替关闭预览。

主角模板

主角模板描述你在新会话中扮演谁。它与角色卡提供的世界和其他人物分开管理。

创建自己的身份

  1. 打开「设置 → 主角模板」。
  2. 选择一个已有模板，点击「复制」；也可以使用页面的新建入口。
  3. 修改名称、别称、性格与背景等内容。
  4. 点击「保存」。
  5. 返回角色卡详情，在创建新会话前选择这个主角。

锁定的内置模板需要先复制再编辑。界面会标明「核心」「内置」或「自定义」等属性；以模板实际显示的可编辑状态为准。

待补截图：主角模板列表、复制和保存按钮，以及身份编辑区域。

怎样填写

名字用于识别主角，别称用于表达同一人物的其他称呼。性格和背景写成适合模型理解的具体信息，例如：

姓名：林舟
别称：林调查员
性格：谨慎，习惯先观察再提问；不轻易向陌生人透露来意。
背景：受委托调查港口失踪案，第一次来到这座小镇。

尽量区分“这个人是什么样的人”和“这一轮准备做什么”。长期身份放进模板，当轮行动写在故事输入框里。

设置默认模板

点击模板旁的星标或详情中的「设默认」。默认模板用于方便新开局选择，创建前仍可改选其他主角。

模板会用于新开局的玩家名称替换和状态初始化。修改模板后，不要把它理解为已经重写所有历史会话；已有会话中的身份和经历需要在本局范围内判断。

主题与界面

打开「设置 → 外观」。先选择浅色、深色或跟随系统，再按需要选择和编辑主题。

主题颜色主要围绕背景色、前景色和强调色调整。查看设置页的实时效果，再回到故事正文检查阅读舒适度。外观修改不改变角色卡内容和写作要求。

待补截图：外观设置中的主题模式、主题颜色和实时预览。

字体与阅读

根据自己的阅读习惯调整字体和字号。界面提供衬线、无衬线、楷体、圆体等字体类别，以及可用字体选项。

更改后回到一篇较长章节，检查正文、输入区和右侧栏是否都适合阅读。不同窗口尺寸下，可见区域会不同。

发送快捷键

打开「设置 → 其他 → 发送快捷键」，选择 Enter 或 Shift+Enter。

此设置作用于扮演区、创世助手和小精灵输入框。选择后，先用一条短输入确认操作习惯；也可以直接点击发送按钮。

当指令或快速提示词候选菜单已经展开时，Enter 可能用于确认候选项。先检查候选是否已插入，再确认发送正文。

快速提示词

「设置 → 快速提示词」用于管理故事输入框里的 # 候选。可以新建、复制、修改名称和标签、编辑插入文本，以及使用 JSON 导入导出。

选中一项后点击「保存」。回到故事输入框输入 #，再输入名称或关键词筛选。选择候选只会插入文本，仍需检查并发送。

这与全局提示词不同：快速提示词需要你在输入框主动选择，不会因为保存在设置里就自动加入每轮请求。

模型分配、任务与日志

管理模型连接

「设置 → 模型配置」把连接信息与助手使用方式分开：先添加连接，再选择兜底模型或单独分配给角色。首次配置步骤见配置模型。

点击连接名称可以编辑；「启用／停用」决定它能否继续作为可用连接使用。删除正在被使用的连接时，界面会提示相关角色和兜底配置的影响。

填写连接后，可以点击“连接并获取模型”获取列表，也可以手动填写模型名。保存前点击“测试模型”：测试会检查基础生成、结构化输出和 Agent 调用，结果为“模型可用”或“部分兼容”时才能保存。修改地址、密钥、模型或推理等级后需要重新测试。

推理等级选项由模型目录中对应供应商和模型的信息提供；未提供等级的模型不会显示可选档位。模型配置页的“更新模型目录”需要手动点击，更新后会刷新推理等级及上下文／输出上限；更新失败时保留已有目录。

更换模型后，再用一轮实际故事确认效果。相同写手换用不同模型，文风、速度、上下文处理和工具执行表现都可能不同。

写手高级设置

在「设置 → 其他」中打开「写手高级设置」，可以调整 Agent 写手可读取的内容，包括当前状态、上一章、历史检索、章节读取、世界书和记忆。

更改后点击「保存更改」。这些选项控制可用的读取能力，并不表示模型每轮一定会读取所有勾选内容。没有明确需求时，可以先保持现有设置。

小精灵

故事右侧栏可以打开「小精灵」进行问答和获取建议。小精灵使用的模型可以在「模型配置 → 角色模型分配」中指定。

创世助手和写手助手还有各自的编辑协作流程。看见助手回复后，应检查它实际修改或提出了什么，再执行页面提供的保存、确认或发送操作；对话文字本身不能代替这些操作的结果。

任务中心

点击侧栏中的「任务」，查看故事解析、酒馆预设提取、章节润色和写手改进等后台任务的进度、失败原因与结果。章节润色和写手改进的结果也从这里打开；写手提案需要确认后才会应用。预设提取完成后，还需要从这里打开审阅，确认片段并保存到资源仓。

普通故事正文生成不会出现在任务中心。正文生成的进度、取消和失败重试，应在故事区的本轮消息和输入区域查看或操作。等待时间较长时，先区分正在执行的是哪一类操作，再检查对应位置，避免连续发起相同请求。

日志与诊断

打开「设置 → 日志」。这里管理日志配置、容量和写作追踪，不是把所有工程日志逐条显示在设置页。

写作追踪可以保存提示词、请求、响应和状态等排错材料，帮助检查某轮为什么生成了这样的结果。清理追踪会失去对应的排错记录，操作前阅读确认提示。

「设置 → 其他」还有开发者模式。是否保留了某轮的完整记录，取决于当时的记录设置和数据是否仍存在；事后开启不能保证补回此前内容。

需要反馈问题时，记录发生位置、操作步骤、错误文字、对应故事与会话，以及是否能稳定重现。分享截图或日志前，隐藏 API Key 和不准备公开的故事内容。

八、常见问题与速查

常见问题

连接已保存，为什么仍不能生成

检查连接是否启用，兜底模型或对应助手是否指向该连接，然后查看连接测试的具体结果。保存成功只代表配置已保存。

如果错误与地址、鉴权、模型不存在或协议有关，优先检查连接信息；如果是结构化输出或 Agent 检查失败，需要结合失败项目判断该模型是否适合对应用途。详见配置模型。

取得模型列表失败，是不是一定不能用

不一定。模型列表和生成请求是不同操作。服务没有返回列表时，可以手动填写服务提供的模型名称，再做生成兼容性测试。不要凭猜测拼写模型名。

角色卡导入成功，故事解析却失败了

这是两个步骤。先查看解析错误并检查基本助手的模型连接；需要时再重试解析。当前解析未完成或失败时可以先开局，详情会显示相应提示。

为什么创建新会话后，之前的剧情不见了

新会话是另一局。回到角色卡详情的历史会话，选择原来的会话继续；也可以从故事顶栏切换已有会话。

生成等待很久，或者只有部分内容

先在故事区检查本轮是否仍在运行、当前阶段和运行详情是否报告失败。普通正文生成不在任务中心显示；任务中心用于故事解析、酒馆预设提取等后台任务。停止生成与完成保存不是同一个结果，部分展示文字也不一定代表已经保存了完整章节。

如果请求失败，记下错误再使用界面提供的重试或编辑后重试操作。不要在状态不明时反复发送相同内容。

世界书词条为什么没有生效

按顺序检查：是否属于本局可用的世界书、词条是否启用、是蓝灯还是绿灯、绿灯关键词是否匹配，以及实际提示词中是否记录了它。

全局世界书只是扩展可参与匹配的词条来源，不保证其中所有词条每轮都进入模型输入。正文没有照写也不能单独证明词条未注入，应结合本轮提示词查看。

修改文风后，为什么上一章没变化

修改写手或世界书主要影响后续生成，不会自动重写已经保存的章节。希望改善已有文章的阅读表达时使用润色；希望改变本轮剧情时考虑撤回或重写，并阅读操作提示。

全局系统提示词有独立的生效范围，当前不注入写手；不要把对写手的要求仅放在那里。

润色稿里发生了新事件，后续会跟着它走吗

不会。润色稿只用于阅读，不替换章节原文，也不参与状态、总结和后续写作。需要改变正式剧情时，应使用对应的章节修改或重写操作。

状态栏没有显示，或者显示内容与预期不同

先确认卡片是否设计了状态栏，相关能力是否启用，再区分“展示没有出现”和“变量没有更新”。普通卡不一定自带 MVU；存在状态栏也不等于所有脚本都兼容。

对有 MVU 的卡，应结合变量和本章变化检查。不要仅通过修改显示文字来判断底层数值已更新。

编辑一章后，后续内容会自动全部更新吗

不会。章节原文编辑的提示明确区分本章状态与总结、故事状态和后续章节。它不是重新运行整段历史；修改前先确认自己是要改文字、改剧情，还是只改善阅读。

故事忘记了重要经历，或者出现设定矛盾

先检查历史总结是否遗漏，相关世界书词条有没有参与本轮输入，再看当前设定是否写清楚。将希望持续生效的信息放在恰当位置，比每轮粘贴全部历史更容易检查。

会话中途修改角色卡或世界书，不会自动修复已有章节中的矛盾。下一轮可以明确说明当前事实，但不要把助手回答当作所有历史已被重算。

创世助手说写好了，为什么角色卡库里没有

检查当前是否只保存了草稿。完成后还需要使用「保存成角色卡」，选择另存或覆盖并确认结果。保存结束后到角色卡详情核对字段和开场，再试玩。

创世 Skill 没有按预期使用

先检查材料是否放在「创世 Skill」类别中、是否为 Markdown，以及名称和说明是否能表达用途。可以在对话中明确要求使用哪份 Skill 和希望解决的问题。

Skill 是方法参考，不是保证模型遵循所有步骤的开关。最终需要检查实际草稿，而不只看助手是否提到了 Skill 的名字。
